# Անվճար հրապարակման ընթացք

Ընտրված է GitHub Pages + գործող Supabase նախագիծը՝ `yumachbfwrxdoypfvyhg`։ Վճարովի Render ծառայություն կամ սկավառակ չի ստեղծվել։

GitHub Pages-ը կսպասարկի պորտֆոլիոն, React-ը և արտահանված Next.js բլոգը։ Supabase Auth-ը կպահպանի գործող հաշիվները։ Տեղական SQLite API-ի տվյալներն ու գործողությունները պետք է տեղափոխվեն Supabase PostgreSQL / Edge Functions՝ պահպանելով առաջադրանքների սեփականատերերի և ադմինի իրավունքների ստուգումները։ SQLite ֆայլը GitHub Pages-ում չի գործարկվում։

Հաջորդ քայլերը՝

1. Կապակցել Supabase-ը և ստուգել գործող նախագծի անվճար պլանը, աղյուսակներն ու քաղաքականությունները։ Չստեղծել նոր նախագիծ և չփոխել պլանը։
2. Ավելացնել առանձնացված աղյուսակներ և RLS քաղաքականություններ՝ չփոխելով գործող `planner_snapshots` տվյալները։ Սովորական հաշիվը կտեսնի միայն իր առաջադրանքները։ Ապրանքներն ու հոդվածները հանրային ընթերցմամբ կլինեն, կառավարումը՝ միայն հաստատված ադմինին։
3. Գների հաշվարկը, պատվերների գրանցումը և մուտքային տվյալների ստուգումը տեղափոխել սերվերային գործառույթներ։ Բրաուզերում տեղադրել միայն հրապարակային բանալին։
4. Կապել գոյություն ունեցող էջերը նոր API-ի հետ՝ տեղական տարբերակը պահպանելով։ Ստուգել երկու հաշիվների մեկուսացումը և գործող ձևերը։
5. Տեղափոխել տեղական տվյալները հաստատված սեփականատերերով։ Բազան կամ անձնական տվյալները չհրապարակել Git-ում։
6. Հրապարակել GitHub Pages-ում և ստուգել իրական հանրային հղումը։ Մինչ այդ նոր backend-ը հրապարակված չի համարվում։

Պահանջվում է Supabase նախագծի կառավարման հասանելիություն։ Միայն հրապարակային բանալին թույլ չի տալիս կատարել անվտանգ schema migration կամ տեղադրել Edge Function։ Գաղտնաբառ կամ գաղտնի բանալի չուղարկել չատում։

Անվճար պլանն ունի օգտագործման սահմաններ, և ցածր ակտիվության դեպքում նախագիծը կարող է դադարեցվել։ Պայմանները՝ https://supabase.com/pricing ։
